# ส้มตำนายหนึ่ง POS (Improved)

ระบบ POS + QR Code Order แบบ single-file ที่ปรับปรุงจาก [uburiram/somtum1pos](https://github.com/uburiram/somtum1pos)

## สิ่งที่แก้ไขและเพิ่มเข้าไป

### ความปลอดภัย
- **PIN ล็อก** หน้า “ร้านค้า” และ “จัดการ” (ค่าเริ่มต้น `1234` — ควรเปลี่ยนทันที)
- ปลดล็อกแล้วอยู่ได้ 10 นาที (รีเซ็ตเมื่อมีการคลิก)
- ยืนยันก่อนลบข้อมูล / Import

### การชำระเงิน
- **PromptPay QR มาตรฐาน EMVCo จริง** (รองรับเบอร์ 10 หลัก และเลขบัตร 13 หลัก)
- ฝังยอดเงินใน QR ได้

### ข้อมูลและรายงาน
- รายงานยอดขายวันนี้ + เมนูขายดี Top 5 + ประวัติออเดอร์ 50 รายการล่าสุด
- **Export / Import JSON** สำรองข้อมูลทั้งหมด
- กรองออเดอร์: กำลังดำเนินการ / ยังไม่ชำระ / ทั้งหมดวันนี้ / เสร็จแล้ว

### UX / คุณภาพโค้ด
- ค้นหาเมนู
- รองรับ URL รูปเมนู
- HTML escape ลดความเสี่ยง XSS
- ซิงค์แท็บเดียวกันผ่าน BroadcastChannel
- Validation ราคา / ชื่อ / PromptPay
- UI ปรับปรุง (filter, badge, empty state)

## วิธีใช้

1. เปิดไฟล์ `index.html` ในเบราว์เซอร์ (Chrome / Edge / Safari แนะนำ)
2. แท็บ **ลูกค้า** — สั่งอาหารได้เลย (ไม่ต้อง PIN)
3. แท็บ **ร้านค้า** / **จัดการ** — ใส่ PIN `1234` (แล้วเปลี่ยนในตั้งค่า)
4. ตั้งค่าเบอร์ PromptPay จริงในหน้าจัดการ → ตั้งค่า/QR
5. พิมพ์ป้าย QR จากหน้าตั้งค่า ติดโต๊ะให้ลูกค้าสแกน

## ข้อจำกัดที่ยังเหลือ (สำคัญ)

ระบบนี้ยังเป็น **client-side ล้วน (IndexedDB)** จึงมีข้อจำกัดดังนี้:

| หัวข้อ | สถานะ |
|--------|--------|
| หลายเครื่อง / หลายมือถือพร้อมกัน | ❌ ข้อมูลไม่แชร์ข้ามเครื่อง (แชร์ได้เฉพาะแท็บในเบราว์เซอร์เดียวกัน) |
| ยืนยันสลิปโอนอัตโนมัติ | ❌ ต้องให้พนักงานกดยืนยันเอง |
| PIN ฝั่ง client | ⚠️ ป้องกันผู้ใช้ทั่วไปได้ แต่ไม่กันผู้ที่เปิด DevTools |
| Backup อัตโนมัติบนคลาวด์ | ❌ ต้อง Export เอง |

**ถ้าต้องการใช้งานจริงหลายเครื่อง** ต้องมี Backend (เช่น Node.js + PostgreSQL / Supabase / Firebase)
